# 章节选择解析与提示修复 — 设计

## 意图

`/漫画 阅读` 与 `/漫画 下载` 按编号选章节，在"单行本卷"与"正篇话"共用编号的漫画上
（如《安达与岛村》：`单行本：第01卷` 与 `第01话` 的 `chapter_number` 都是 1）直接失灵：

- `阅读 安达与岛村 1` 只回一串裸 ID，用户无从判断哪一个是正篇；
- `阅读 安达与岛村 第01话` 输出 `第 第01话 话存在多个章节`（模板重复了"第/话"）；
- `阅读 安达与岛村 01卷` 被判"章节号无效"——解析器只认 `话/話/章`，且完全不看章节名。

目标：让用户在章节列表里**看到什么就能输入什么**，并且提示能自解释、绝不静默选错。

## 真实数据（已用 http://100.87.49.15:9330 验证，manga 151《安达与岛村》）

71 个章节，含 `第01话`(2531,1)、`番外篇1`(2532,1)、`单行本：第01卷`(2539,1)、`第05话`(2527,5)、
`第05话后篇`(2526,5)、`07卷附录`(2477,7)、`第07话`(2524,7)、`第38.2话`(2488,38.2)、`第09话`(2522,9)
等，覆盖前导零、小数、重号、卷/话混排、卷附录、番外等形态。下面的规则与预期都以它为准。

## 目标 / 非目标

- 目标：编号、`第X话`、`第X卷`、章节名、`ID:数字` 都能用；歧义提示逐条列出名字 + ID；
  帮助与错误示例与该能力一致。这些写法只服务于命令层：AI 工具拿到完整章节列表（含 `chapter_id`）
  后按 ID 选择，`selector` 保持 `latest`/`list`/章节号/`ID:数字`。
- 目标：任何"可能选错"的情形宁可报错并列出候选，也不静默选一个。
- 非目标：中文数字（"第一卷"）→ 阿拉伯数字换算（但按名称/包含匹配仍可能命中）；不做"自动猜正篇"——
  用户已拍板：编号命中多个时**始终让用户选**。

## 匹配核心

新增纯函数（`suwayomi/service.py`）：

```
match_chapters(chapters, text) -> (candidates, kind)
kind ∈ {"matched", "ambiguous", "unit_mismatch", "name_conflict", "not_found"}
```

`ID:` 分支保留在 `resolve_chapter` 与 `ai_service` 各自入口（它们的错误文案不同）。
`resolve_chapter` 只负责把 `kind` 渲染成文案。`match_chapters` 仅用于命令层（阅读/下载）；
`ai_service._select_chapter_candidates` 继续只认 `latest`/`list`/章节号/`ID:数字`——
Agent 会拿到章节列表和稳定 `chapter_id`，不需要名称或卷解析，避免把不稳定的名字写进工具契约。

### 归一化（名称比较键）

`key(text)`：NFKC（全角→半角）→ t2s（繁→简）→ casefold → 空白与装饰性标点（`:：·・、，。~()[]【】
{}!?！？"'“”‘’#*_`）删除 → 数字串**整数部分**前导零剥离（`(?<![\d.])0+(?=\d)`）。**保留 `.` 与 `-`**，
不把 `3.8` 并成 `38`、不把 `1-2` 并成 `12`；小数点后的零保留，`3.08` 与 `3.8` 是不同 key。

再加一道**数字序列校验**：比较两个 key 时，`\d+(?:\.\d+)?` 抽出的数字序列必须相同。
这挡住"标点删除导致数字粘连"的极端碰撞（`第1-2话` vs `第12话`）。

### 单位（话/卷）判定

- 单位表：章 `话/話/章/回/集`，卷 `卷/冊/册`。
- 只认**紧跟在该编号后面**的单位字符：在 key 里找 `(\d+(?:\.\d+)?)[单位]`（数字前不能紧邻数字），
  数字按**数值**比对，所以 `38.50话` 与 `38.5` 等价。`07卷附录` 对编号 7 是"卷"，
  `第15话` 对编号 5 不算"话"（不留 `(?<!\d)` 会被前缀数字误判）。同一标题同时出现两种单位
  （如 `第5卷 第5话`）时集合里保留两者，按请求的单位命中。
- 输入带单位时：候选按同名单位过滤。
  - 过滤后非空 → 继续（`第1卷` → 只剩 `单行本：第01卷`）；
  - 过滤后为空、但候选名字里带**另一种**单位 → `unit_mismatch`，**不跨单位静默命中**
    （`第3卷` 不会读成 `第03话`，而是告知"编号 3 只有第03话"）；
  - 候选名字根本没单位标记 → 无法判断，保留候选。
- 输入不带单位（`1`、`38.5`）→ 不做单位过滤，编号即权威。

### 解析顺序

1. `ID:<n>`（NFKC 后识别全角 `ＩＤ：`）→ 精确。
2. 名称精确优先：输入不是纯数字（`5`、`38.5`）时，先在全表做名称 key 精确匹配——
   唯一 → 命中，多个 → 列候选。这样显示名为 `第5话` 而源站编号是 12 时，`第5话` 仍按其显示名命中；
   裸数字不走这步，仍以 `#N` 列为准。
3. 数字：`parse_chapter_number_text` 扩展为剥 `#`、`第` 前缀 + `话/話/章/回/集/卷/冊/册` 后缀。
   - 零命中 → `not_found`；
   - 单位过滤 / `unit_mismatch`（见上；单位按**数值**比对，`38.50话` 也算 38.5 的话）；
   - 候选名字与输入 key 相等（含数字序列校验）且唯一 → `matched`；
   - 候选唯一 → `matched`（但若名称显式写着**同单位的不同编号** → `name_conflict`，
     例：`第5话` 命中 chapterNumber=5 但名字叫 `第15话`，不静默读，提示用 `5` 或 ID 确认）；
   - 其余 → `ambiguous`。
4. 非数字（数字解析失败）：名称"包含"匹配（key 长度 ≥ 2；输入以数字开头/结尾时加数字边界，
   且 `.`/`-` 后接数字视为数字延续，`番外1` 不会匹配 `番外1.5`/`番外1-2`）；唯一 → `matched`，
   多个 → `ambiguous`，零个 → `not_found`。

### 预期结果（真实语料）

| 输入 | 结果 |
|---|---|
| `1` | ambiguous：`第01话` / `番外篇1` / `单行本：第01卷` |
| `第1话`、`第01话`、`第１话`、`第1話` | 2531 `第01话` |
| `第1卷`、`第01卷`、`01卷`、`第2卷` | 单行本对应卷 |
| `第5话`、`第05话` | 2527 `第05话`（不是后篇） |
| `第05话后篇` | 2526 |
| `5` | ambiguous：`第05话后篇` / `第05话` |
| `第7卷` | 2477 `07卷附录`；`7` → 与 `第07话` 一起列出 |
| `第3卷` | unit_mismatch：只有 `第03话` |
| `第38.2话` | 2488 |
| `番外` | ambiguous：`番外篇1` / `番外篇2` |
| `附录`、`番外篇1`、`单行本：第01卷` | 唯一命中 |
| `单行本` | ambiguous：两个单行本卷 |

| `ＩＤ：2531`、`id:2531` | 2531 |
| `abc`、`卷`、空 | not_found（副串匹配 ≥2 字） |

## 文案

歧义：

```
「1」匹配到 3 个章节，可用章节名或 ID 指定：
  #1 第01话 (ID:2531)
  #1 番外篇1 (ID:2532)
  #1 单行本：第01卷 (ID:2539)
用法: /漫画 阅读 安达与岛村 第01话
```

- 用法行优先给出**可复制且能唯一命中**的章节名（喂回 `match_chapters` 必须命中该候选、无空格、长度合规）；
  优先选规范化形如 `第N话` 的正篇候选。找不到这样的名称（重名、多词、异常字符）时退回 `ID:<id>`，
  标题同时改为"请用 ID 指定"。

- 行格式与 `/漫画 章节` 列表一致（`fmt_chapter_label`）；最多 10 行，超出补 `… 共 N 个`。
- 输入按用户原文「」引用，不再拼进"第…话"模板（修掉重复"第/话"）。
- 候选名 `sanitize_for_message`，`manga_name_or_id` 限长。

单位不符：

```
「第3卷」未匹配到卷，编号 3 只有：
  #3 第03话 (ID:2529)
用法: /漫画 阅读 安达与岛村 ID:2529
```

名称冲突：

```
编号 5 的章节名是「第15话」，与输入「第5话」不一致：
  #5 第15话 (ID:2)
用法: /漫画 阅读 安达与岛村 5  或  ID:2
```

未找到：

```
未找到「番外3」对应的章节。可用：1、38.5、第5话、第1卷、章节名，或 ID:123；
也可先 /漫画 章节 安达与岛村 查看列表。
```

帮助文案（`main.py` 的 `📚 阅读与下载`、`阅读`/`下载` docstring 与用法提示）同步列出这几种写法。

## 影响面

- `suwayomi/service.py`：新增 `key`/单位/`match_chapters`，重写 `resolve_chapter`，扩展后缀表。
- `suwayomi/ai_service.py`：`selector` 收窄为 `latest`/`list`/章节号/`ID:数字`，不参与名称解析。
- `main.py`：帮助/docstring/用法文本。
- 文档：`docs/dev/development.md` 关键函数、`CHANGELOG.md`、`ai_tools.py` selector 描述。
- 测试：`tests/test_service.py`（真实语料夹具 + 合成边界）、`tests/test_ai_service.py` 固定
  selector 的编号/ID 语义并拒绝名称与卷。

## 留给实现者

- 候选顺序沿用章节列表顺序，不额外排序。
- 名称匹配不做"输入包含章节名"的反向包含，避免过度匹配。
