# 按搜索结果编号引用漫画 — 设计

## 意图

`/漫画 搜索` 的编号目前只有 `/漫画 订阅` 能消费（`_search_cache` 的唯一读者），
想接着看某一部必须重新输入标题或手抄 ID：

```
/漫画 搜索 安达与岛村     → [#3] 安达与岛村 [连载中]（拷贝漫画 (ZH)）
/漫画 阅读 3 5            → 现在: 未找到该漫画（3 被当成 manga ID）
```

同时裸数字已经被漫画 ID 占用，直接放宽会产生 `/漫画 阅读 9` 的双重语义。
**决定：让裸数字只表示搜索编号，漫画 ID 一律写成 `ID:数字`。**

这既是把 `订阅` 的既有语义推广到其余三个命令，也顺手让全插件的引用语法统一
（章节选择早就在用 `ID:2531`）。

## 用户可见行为

| 输入形态 | 解释 | 适用命令 |
|---|---|---|
| `ID:151` / `id：151` / `ＩＤ：１５１` | 漫画 ID（NFKC + 忽略大小写与冒号后空格） | `章节` `阅读` `下载` `取消订阅` |
| 纯数字 `3` | **本次会话最近一次搜索的第 3 条结果**（600s 内、且是实际展示过的编号） | `章节` `阅读` `下载` `订阅` |
| 其他文本 | 订阅标题子串 → 数据库标题子串（原逻辑） | `章节` `阅读` `下载` `取消订阅` |

不存在「裸数字在缓存未命中时回退成 ID」的分支。搜索编号不存在时给**教学式报错**，
而不是猜。

### 交互示例

```
/漫画 搜索 安达与岛村
🔍 搜索结果（3 条，按相关度排序）:
  [1] 安达与岛村 - 连载中（拷贝漫画 (ZH)）
  ...
  [3] 安达与岛村官方同人集 - 连载中（再漫画 (ZH)）

/漫画 阅读 3 5        → 📖 正在加载「安达与岛村官方同人集」第5话...
/漫画 章节 3           → 📖「安达与岛村官方同人集」… 章节列表
/漫画 下载 3 5 pdf     → 打包发送

/漫画 阅读 ID:151 5    → 漫画 151
```

多结果引导、`我的订阅`、`取消订阅` 回执统一印可解析的 `ID:151`，
用户「抄 ID」的动作天然带前缀。

## 目标 / 非目标

- 目标：`章节` / `阅读` / `下载` 能消费搜索结果编号，与 `订阅` 共用同一套编号。
- 目标：任何失败都给出下一步可执行的写法（`ID:N` / 重新搜索 / 用名称）。
- 目标：全插件只保留一种「漫画 ID must be prefixed」语法，帮助、报错、清单一致。
- 非目标：不引入 `#3` 一类新前缀（搜索结果卡片布局保持原样，不改样式）。
- 非目标：不给旧行为留开关（兼容开关等于把双重语义再放回来）。
- 非目标：不改搜索编号 TTL（600s 硬编码）；不改 `阅读`/`下载` 的多词标题切分缺陷
  （`阅读` 仍只吃单 token 名称，另案处理）。
- 非目标：`取消订阅` 不消费搜索编号（它的宇宙是订阅列表，不是搜索结果）。
- 非目标：AI 工具、WebUI 不动（它们用整数 `manga_id` / `manga_id` 字段）。
- 反目标：静默挑一个候选、或报错后仍需用户自己猜格式。

## 解析核心

### `parse_manga_ref`（新增纯函数，`suwayomi/service.py`）

```python
def parse_manga_ref(text: str) -> tuple[str, int | str]:
    """→ ("id", int) | ("index", int) | ("name", 原始文本)"""
```

- `norm = unicodedata.normalize("NFKC", str(text)).strip()`（全角数字/冒号/字母一并归一）
- `re.fullmatch(r"id\s*[:：]\s*(\d+)", norm, re.IGNORECASE)` → `("id", n)`
- `re.fullmatch(r"\d+", norm)` → `("index", n)`
- 其余 → `("name", str(text).strip())`（保留原文，名称比较仍走 `normalize_zh`）

### `resolve_manga` 新顺序（`service.py:638`）

```python
async def resolve_manga(client, sub_mgr, umo, name_or_id, cmd, *, index_lookup=None)
```

1. `parse_manga_ref` → `id`：`get_manga(n)`；失败 → 「未找到 ID:{n} 的漫画。」
   （不再吞掉错误回落到名称匹配）
2. → `index`：
   - `index_lookup(umo, str(n))` 返回 `(manga|None, count)`
   - 命中 → 直接返回该 `Manga`（无需再查源）
   - 未命中 → 教学式报错（见下），**不**回退 ID、**不**回退名称
   - `index_lookup is None`（理论上只有非命令调用）→ 按「无搜索结果」报错
3. → `name`：订阅标题子串（`normalize_zh` 包含）→ 数据库标题 `includes`，行为不变。

`index_lookup` 由 `main.py` 注入，缓存仍留在插件上（与 `订阅` 共用）：

```python
def _search_index_lookup(self, umo: str, key: str) -> tuple[Manga | None, int]:
    cache = ttl_cache_lookup(self._search_cache, umo, _CACHE_TTL)
    if not cache:
        return None, 0
    return cache.get(key), len(cache)
```

`count` 用于生成「本次搜索只显示了 1–N 号」的范围提示。

### 教学式报错（命中 ID 探测存在时优先）

未命中时用 `client.get_manga(n)` 探测该 ID 是否存在（一次查询，失败只记 debug），
按「缓存是否为空 → ID 是否存在 → 是否越界」的顺序选文案。
用法行里的 `<章节>` 占位符只对 `阅读`/`下载` 输出（`章节` 不接受章节参数，
写 `<章节>` 会让用户复制到一条必然失败的指令）。

1. **缓存为空（过期 / 没搜过）且 ID 存在**
   ```
   当前没有可用的搜索结果编号（搜索结果 10 分钟内有效）。
   若你指的是漫画 ID，请用: /漫画 阅读 ID:3 <章节>
   ```
2. **缓存为空且 ID 不存在**
   ```
   当前没有可用的搜索结果编号（搜索结果 10 分钟内有效）。
   请先「漫画 搜索 <关键词>」，或用「ID:数字」/ 名称指定漫画。
   ```
3. **缓存非空（编号越界）且 ID 存在**
   ```
   3 是漫画 ID，但不在本次搜索结果里。
   改用: /漫画 阅读 ID:3 <章节>
   ```
4. **缓存非空且 ID 不存在**
   ```
   本次搜索结果只有 1–{count} 号，没有 {n} 号。
   请重新「漫画 搜索」，或用名称指定漫画。
   ```

缓存为空时**不**先说「N 是漫画 ID」：搜索已过期或本会话从未搜索，
此时把用户引向一个碰巧存在的 ID 会读到另一部漫画。
`cmd` 用于拼用法行；帮助文本与 docstring 同步更新。

## 文案与格式改动

- `resolve_manga` 多结果引导：`ID 151: …` → `ID:151: …`，示例改
  `/漫画 {cmd} ID:{first_id}`（`service.py:679`、`683`）。
- `我的订阅` 文本 `- ID: 151` → `- ID:151`；卡片 detail 同步去空格。
- `取消订阅` 成功回执 `（漫画 ID: 151）` → `（ID:151）`。
- 文本模式搜索结果尾部补一行：
  `编号也可用于「漫画 阅读 <编号> <章节>」（10 分钟内有效）`。
  **卡片 footer 不改**（避免卡片换行/布局回归，卡片用户靠帮助与报错学习）。
- 帮助：`📚 阅读与下载` 段落把 `<漫画名或ID>` 改成 `<漫画名或 ID:编号>`，
  加一行说明搜索编号 10 分钟有效；`搜索` 段落点一句编号可复用。

## 兼容与迁移

- **破坏性**：`章节|阅读|下载 151 …` 不再当 ID，必须写 `ID:151`；
  `取消订阅 151` 同理。过期后不再有任何回落，只能靠报错文案纠正。
- 纯数字标题（如《86》）无法再用裸名称引用，出口是：`搜索 86` → 结果编号，
  或 `我的订阅` → `ID:86`。写进 README 的注意事项。
- 搜索编号只在写出它的会话里、600s 内有效；`/reset`、WebUI 保存配置会清空。
- 编号只覆盖实际展示过的行：开启排序时是前 `search_display_limit`（默认 20）条，关闭排序时是全部结果；超出按越界文案提示。

## 留给实现者

- 标题/来源一律 `sanitize_for_message` 并限长；报错里的用户输入也过清洗。
- 序号命中/未命中各记一条 `logger.debug`（编号、manga_id、缓存条数），便于排查串会话。
- ID 探测失败（网络错误）按「ID 不存在」处理，但不能让探测异常冒泡。
- 不要给成功路径加「（搜索结果 #3）」标记：裸数字语义已唯一，标记只会是噪音。
- `订阅` 的解析路径保持不变，只把 `_get_cached_manga` 与 `_search_index_lookup`
  收敛到同一缓存读取逻辑。
